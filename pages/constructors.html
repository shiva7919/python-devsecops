Constructors

The constructor is the code that runs the moment an object is created — it's where you set up whatever that object needs to exist in a valid state, before anyone calls a method on it.

Theory

In Python, the constructor is the __init__() method. Python calls it automatically when you write ClassName(...); you never call __init__() directly yourself. Its job is to set initial attribute values on self.

Default vs. parameterized constructors

Python doesn't have a separate "default constructor" syntax the way some languages do — instead, you give __init__() parameters, and give those parameters default values for anything optional.

constructor_styles.py
class Server:
    # "default" behavior comes from giving every param a default
    def __init__(self, hostname="unnamed-host", role="web"):
        self.hostname = hostname
        self.role = role

# uses the defaults
generic = Server()

# parameterized: caller supplies real values
db01 = Server("db-01", "database")

Constructing server objects

server_constructor.py
class Server:
    def __init__(self, hostname, ip_address, cpu_cores=2, memory_gb=4):
        self.hostname = hostname
        self.ip_address = ip_address
        self.cpu_cores = cpu_cores
        self.memory_gb = memory_gb
        self.tags = []  # every server starts with an empty tag list

api01 = Server("api-01", "10.0.2.5", cpu_cores=4, memory_gb=8)
print(api01.hostname, api01.cpu_cores)
Warning

Never use a mutable default like tags=[] as a parameter default — Python creates that list once and every instance would share it. Assign the empty list inside __init__, as shown above, not in the parameter list.

Constructing cloud resources

cloud_resource_constructor.py
class CloudResource:
    def __init__(self, resource_id, resource_type, region, tags=None):
        self.resource_id = resource_id
        self.resource_type = resource_type
        self.region = region
        self.tags = tags if tags is not None else {}

bucket = CloudResource("company-backups-2026", "s3_bucket", "us-east-1",
                        tags={"env": "prod"})

This is the correct pattern for a mutable default: accept None and build the real default inside the constructor body.

Constructing monitoring alerts

monitoring_alert_constructor.py
import datetime

class MonitoringAlert:
    def __init__(self, metric, value, threshold, triggered_at=None):
        self.metric = metric
        self.value = value
        self.threshold = threshold
        # default the timestamp to "now" if the caller didn't supply one
        self.triggered_at = triggered_at or datetime.datetime.utcnow()

alert = MonitoringAlert("cpu_percent", 96, 90)
print(f"{alert.metric} breached at {alert.triggered_at}")

Knowledge check

Summary

  • __init__() is Python's constructor — it runs once, automatically, when an object is created.
  • Give parameters defaults to make a constructor flexible without requiring every caller to specify everything.
  • Never use a mutable object (list, dict) as a default parameter value — default to None and build it inside the method.
