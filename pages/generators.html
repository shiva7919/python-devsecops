Generators

A 40GB log file will not fit in memory as a Python list. A generator lets you process it one line at a time instead, holding almost nothing in memory regardless of how large the underlying data is. This is the difference between a script that works in the demo and one that survives production log volumes.

Theory

A normal function computes its entire return value before handing it back. A generator function — one that uses yield instead of return — produces values one at a time, pausing after each yield until the caller asks for the next one. This is lazy evaluation: nothing is computed until it's actually needed.

Syntax

generators_syntax.py
def countdown(n):
    while n > 0:
        yield n
        n -= 1

for value in countdown(3):
    print(value)   # 3, 2, 1 — computed one at a time

Calling countdown(3) doesn't run the function body at all — it returns a generator object. The body only executes as the loop pulls values, one yield at a time.

Memory: list comprehension vs. generator

memory_comparison.py
# builds the entire list in memory before returning — fine for small n
squares_list = [x * x for x in range(1000000)]

# produces one value at a time — near-constant memory regardless of n
squares_gen = (x * x for x in range(1000000))
Tip

Swapping square brackets [] for parentheses () in a comprehension turns it into a generator expression — no yield required for simple cases.

Practical examples

Streaming a large log file

stream_logs.py
def stream_errors(path):
    with open(path) as f:
        for line in f:
            if "ERROR" in line:
                yield line.strip()

# only one line is ever held in memory at a time, even for a 40GB file
for error_line in stream_errors("/var/log/app/prod.log"):
    print(error_line)

Streaming SIEM events

siem_events.py
def high_severity_events(events):
    """events: any iterable of event dicts, e.g. a paginated API client"""
    for event in events:
        if event.get("severity") in ("high", "critical"):
            yield event

Reading a huge file in fixed-size chunks

chunked_reader.py
def read_in_chunks(path, chunk_size=8192):
    with open(path, "rb") as f:
        while True:
            chunk = f.read(chunk_size)
            if not chunk:
                break
            yield chunk

Streaming Kubernetes watch events

k8s_events.py
def pod_restart_events(watch_stream):
    """watch_stream: an iterable yielding raw k8s event dicts"""
    for event in watch_stream:
        if event["type"] == "MODIFIED" and event["object"].get("restart_count", 0) > 0:
            yield event
Note

A generator can only be iterated once — once exhausted, looping over it again yields nothing. If you need to process the same data twice, materialize it into a list, or re-create the generator.

Knowledge check

Summary

  • Generators use yield to produce values lazily, one at a time, instead of building an entire result up front.
  • They're the right tool for streaming large log files, event feeds, and API responses without exhausting memory.
  • Generators are single-use — once exhausted, they need to be re-created to iterate again.
