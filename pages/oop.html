Object-Oriented Programming

Once your scripts start tracking more than a couple of related values per "thing" — a server's name, IP, status, and role, say — passing them around as separate variables or loose dictionaries gets error-prone. A class lets you define that "thing" once, as a type, and every instance of it behaves consistently.

Why OOP shows up in automation frameworks

Tools like Ansible, Terraform providers, and Kubernetes client libraries are built almost entirely out of classes: a Server, a Deployment, a Pod. Modeling your own automation the same way means every server behaves the same way, every alert has the same shape, and adding a new capability means adding one method instead of hunting down every place a dictionary key is used.

Theory

A class is a blueprint. An object (or instance) is a specific thing built from that blueprint. Attributes are the data an object holds; methods are the functions it can perform on itself.

Syntax

oop_syntax.py
class Server:
    def __init__(self, hostname, ip_address, role="web"):
        self.hostname = hostname
        self.ip_address = ip_address
        self.role = role
        self.is_online = True

    def describe(self):
        status = "online" if self.is_online else "offline"
        return f"{self.hostname} ({self.ip_address}) — {self.role}, {status}"

web01 = Server("web-01", "10.0.1.10")
print(web01.describe())

Modeling infrastructure as classes

Container

container.py
class Container:
    def __init__(self, image, cpu_limit="500m", memory_limit="256Mi"):
        self.image = image
        self.cpu_limit = cpu_limit
        self.memory_limit = memory_limit
        self.status = "pending"

    def start(self):
        self.status = "running"
        return f"{self.image} is now running"

Deployment and KubernetesCluster

deployment.py
class Deployment:
    def __init__(self, name, replicas, image):
        self.name = name
        self.replicas = replicas
        self.image = image

    def scale(self, new_replica_count):
        self.replicas = new_replica_count
        return f"{self.name} scaled to {new_replica_count} replicas"


class KubernetesCluster:
    def __init__(self, name, region):
        self.name = name
        self.region = region
        self.deployments = []

    def add_deployment(self, deployment):
        self.deployments.append(deployment)

    def total_replicas(self):
        return sum(d.replicas for d in self.deployments)

FirewallRule and SecurityAlert

security_classes.py
class FirewallRule:
    def __init__(self, port, protocol, source_cidr, action="ALLOW"):
        self.port = port
        self.protocol = protocol
        self.source_cidr = source_cidr
        self.action = action

    def is_overly_permissive(self):
        return self.source_cidr == "0.0.0.0/0" and self.action == "ALLOW"


class SecurityAlert:
    def __init__(self, source_ip, severity, description):
        self.source_ip = source_ip
        self.severity = severity
        self.description = description
        self.acknowledged = False

    def acknowledge(self):
        self.acknowledged = True

Pipeline and MonitoringAlert

pipeline_and_alerts.py
class Pipeline:
    def __init__(self, name, stages):
        self.name = name
        self.stages = stages
        self.current_stage = 0

    def advance(self):
        if self.current_stage < len(self.stages) - 1:
            self.current_stage += 1
        return self.stages[self.current_stage]


class MonitoringAlert:
    def __init__(self, metric, value, threshold):
        self.metric = metric
        self.value = value
        self.threshold = threshold

    def is_breached(self):
        return self.value > self.threshold
Note

self refers to the specific instance a method was called on. It's always the first parameter of an instance method, and Python passes it automatically — you never supply it yourself when calling web01.describe().

Summary

  • Classes are blueprints; objects are specific instances built from them.
  • Attributes hold an object's data; methods define what it can do.
  • Automation frameworks lean on OOP so that every server, pod, or alert behaves consistently.
