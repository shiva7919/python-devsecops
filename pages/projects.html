Mini Projects

Ten build-from-scratch projects that combine everything from the course. Each one is scoped to a single sitting (1–3 hours) and produces a real, runnable tool.

Build: a script that gathers hostname, OS, CPU count, memory, and disk usage into a single report using platform, os, and shutil.

Requirements: a SystemInfo class with a to_dict() method; print the report as formatted text and optionally as JSON.

Stretch goal: write the report to a timestamped file so it can be diffed against a previous run.

Build: a command-line tool that reads a log file and reports counts by severity, the top 5 most frequent error messages, and the busiest hour.

Requirements: use a generator to stream the file; use a dict to tally counts; accept the file path as a command-line argument via sys.argv.

Stretch goal: support multiple log files in one run and merge the results.

Build: a poller that checks a list of services (simulated or real via requests.get against health endpoints) on an interval and prints status changes.

Requirements: a Service class per Lab 03; track state transitions (only print when status changes, not every poll); handle connection errors gracefully.

Stretch goal: write status changes to a small history log file with timestamps.

Build: a directory backup tool with compression and retention rotation, extending Lab 08.

Requirements: create_backup(), rotate_backups(keep=N), and a summary printed at the end (files backed up, archive size, archives remaining).

Stretch goal: support excluding paths via a simple ignore-pattern list.

Build: a function-based checker that scores a password against length, character-class, and common-password-list rules.

Requirements: return a score (0–100) and a list of specific reasons for any deductions, not just pass/fail.

Stretch goal: check the password against a small local list of the 100 most common leaked passwords and reject an exact match outright.

Build: extend Lab 04 into a standalone tool that exits with a non-zero status code if any container is unhealthy — suitable for a CI health gate.

Requirements: a ContainerReport class; a clear pass/fail summary printed to stdout; correct use of sys.exit().

Stretch goal: add a --json flag that prints machine-readable output instead of the human-readable summary.

Build: given a list of simulated pod/deployment dicts, generate a report of total CPU/memory requested per namespace.

Requirements: a KubernetesCluster class per Module 05; a generator that filters by namespace; totals computed with sum().

Stretch goal: flag namespaces that exceed a configurable resource quota.

Build: extend Lab 07's brute-force detector into a general-purpose security event parser that classifies events by type (failed login, privilege escalation, firewall block).

Requirements: a SecurityAlert class per Module 05; a generate_report() function per Module 04; output sorted by severity.

Stretch goal: deduplicate repeated alerts from the same source within a time window.

Build: a small wrapper class around the requests library for calling a JSON API (e.g. a status page or public API), with retry logic on failure.

Requirements: an APIClient class with __init__(self, base_url, api_key=None); a get(path) method with retries using a loop; proper error handling for non-200 responses.

Stretch goal: add basic response caching so repeated calls within a short window don't hit the network again.

Build: a tool that hashes a directory's files (SHA-256) and detects any changes against a saved baseline — a simplified file integrity monitor.

Requirements: use hashlib to compute file hashes; store the baseline as JSON; a compare() function that reports added, removed, and modified files.

Stretch goal: use a generator to hash files lazily so scanning a very large directory tree doesn't stall the whole run before reporting anything.
