Functions

A function packages a task — check disk space, restart a service, validate an IP — into something you can name, reuse, and test in isolation. Once operational logic lives in functions instead of a wall of top-to-bottom script, it becomes something you can build a real automation tool out of.

Theory

Define a function with def, a name, and a parameter list. Whatever the function computes is handed back to the caller with return — a function that doesn't explicitly return anything returns None.

Syntax

functions_syntax.py
def greet_engineer(name, shift="day"):
    return f"Welcome {name}, you're on the {shift} shift."

print(greet_engineer("Priya"))
print(greet_engineer("Marcus", shift="night"))

shift="day" is a default parameter — callers can omit it. Use *args and **kwargs when a function needs to accept a variable number of arguments.

Reusable automation functions

Below is a small library of the kind of functions you'll write constantly in an infra or security role. Each does one job and returns a value the caller can act on.

check_disk_space()

check_disk_space.py
def check_disk_space(used_gb, total_gb, threshold=85):
    """Return True if disk usage percentage is below threshold."""
    percent_used = (used_gb / total_gb) * 100
    return percent_used < threshold

print(check_disk_space(72, 100))   # True
print(check_disk_space(91, 100))   # False

restart_service()

restart_service.py
def restart_service(service_name, max_attempts=3):
    for attempt in range(1, max_attempts + 1):
        print(f"[{service_name}] restart attempt {attempt}")
        # in real code: subprocess.run(["systemctl", "restart", service_name])
        success = True  # placeholder for actual result
        if success:
            return True
    return False

def deploy_application(image, replicas=3, namespace="default"):
    print(f"deploying {image} -> namespace={namespace}, replicas={replicas}")
    return {"image": image, "replicas": replicas, "namespace": namespace, "status": "deployed"}

validate_yaml()

validate_yaml.py
import yaml

def validate_yaml(path):
    try:
        with open(path) as f:
            yaml.safe_load(f)
        return True, "valid"
    except yaml.YAMLError as e:
        return False, str(e)

search_logs()

search_logs.py
def search_logs(path, keyword):
    matches = []
    with open(path) as f:
        for line_num, line in enumerate(f, start=1):
            if keyword in line:
                matches.append((line_num, line.strip()))
    return matches

validate_ip()

validate_ip.py
import ipaddress

def validate_ip(address):
    try:
        ipaddress.ip_address(address)
        return True
    except ValueError:
        return False

print(validate_ip("10.0.4.12"))   # True
print(validate_ip("999.1.1.1"))  # False

generate_report()

generate_report.py
def generate_report(findings):
    """findings: list of dicts like {'host': ..., 'issue': ..., 'severity': ...}"""
    lines = [f"Security Report — {len(findings)} findings"]
    for f in findings:
        lines.append(f"  [{f['severity'].upper()}] {f['host']}: {f['issue']}")
    return "\n".join(lines)
Tip

Write a docstring (the triple-quoted string right under def) for every function that isn't trivially obvious — it's the first thing a teammate reads before touching your automation code.

Summary

  • Functions turn one-off logic into named, reusable, testable units.
  • Default parameters and *args/**kwargs make functions flexible for different callers.
  • A small library of well-named functions (check_disk_space, validate_ip, etc.) is the foundation most automation tools are built from.
